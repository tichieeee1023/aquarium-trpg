# 00:37 AM

> **심야 지하철에서 살아남는 텍스트 로그라이크 TRPG 웹 게임**  
> React의 상태 관리와 조건부 분기, D20 판정 시스템을 중심으로 제작한 인터랙티브 프론트엔드 프로젝트입니다.

---

## 프로젝트 소개

**00:37 AM**은 막차가 끊긴 심야 지하철을 배경으로 한 짧은 생존형 텍스트 로그라이크 게임입니다.

플레이어는 직장인 캐릭터의 성향을 선택하고, D20 주사위로 그날의 컨디션을 결정한 뒤  
객차 → 터널 → 승강장 → 환승 상가 → 환기탑으로 이어지는 스테이지를 탐사합니다.

각 행동은 **행동력(AP), HP, SAN, 배터리, 소지품, 조사 기록, 시나리오 플래그**에 영향을 주며,  
이전 선택과 획득한 도구에 따라 이후 선택지와 최종 엔딩이 달라집니다.

단순한 텍스트 출력보다 **상태 변화에 따라 UI와 스토리가 함께 전환되는 구조**를 만드는 데 집중했습니다.

---

## 주요 기능

### 1. 캐릭터 성향 선택

게임 시작 시 5가지 직장인 archetype 중 하나를 선택합니다.

- 분석형 엔지니어
- 헬스 마니아
- 러너
- 협상가
- 한방주의자

각 성향은 서로 다른 주 능력치와 시작 아이템을 가지며, 이후 D20 판정에 영향을 줍니다.

---

### 2. D20 주사위 판정 시스템

TRPG의 D20 판정 방식을 웹 인터랙션으로 구현했습니다.

```text
최종 판정값 = D20 + 능력치 보정치 + 상황 보너스
```

- Natural 1 : 대실패
- Natural 20 : 대성공
- STR / DEX / INT / WILL / LUK 기반 판정
- 캐릭터 특성 및 획득 정보에 따른 추가 보정
- 판정 중 주사위 애니메이션과 효과음 제공

---

### 3. 스테이지 기반 탐사와 분기

게임은 총 5개의 주요 구간으로 구성됩니다.

```text
캐릭터 생성
   ↓
암전된 6호차
   ↓
선로 터널
   ↓
의태된 승강장
   ↓
환승 상가
   ↓
환기탑
   ↓
ENDING
```

각 스테이지에서는 제한된 행동력 안에서 조사 대상을 선택해야 합니다.

무엇을 조사했는지, 어떤 도구를 얻었는지, 특정 위화감을 발견했는지에 따라  
다음 스테이지의 생존 가능성과 선택지가 달라집니다.

---

### 4. 상태 기반 게임 엔진

복잡한 게임 진행 상태를 하나의 전역 상태 트리로 관리합니다.

주요 상태 예시:

- 현재 스테이지
- 캐릭터 능력치
- HP / SAN
- 행동력
- 배터리
- 인벤토리
- 조사 완료 지점
- 시나리오 플래그
- D20 판정 상태
- 시스템 로그
- 엔딩 데이터

`useReducer`를 중심으로 상태 변경을 처리하고,  
스테이지별 이벤트 로직은 별도의 handler로 분리했습니다.

```text
useGameEngine
 ├─ gameReducer
 ├─ stageHandlers
 │   ├─ stage0Handlers
 │   ├─ stage1Handlers
 │   ├─ stage2Handlers
 │   ├─ stage3Handlers
 │   ├─ stage4Handlers
 │   └─ stage5Handlers
 └─ diceEngine
```

UI 컴포넌트에서 시나리오 처리 로직이 지나치게 커지지 않도록  
**화면 / 데이터 / 상태 / 스테이지 로직을 분리**한 것이 프로젝트의 핵심 구조입니다.

---

### 5. 아이템과 조건부 이벤트

조사 중 획득한 아이템은 단순 수집 요소가 아니라 실제 분기 조건으로 사용됩니다.

예를 들어 특정 도구가 없으면 탈출 자체가 불가능하거나,  
이전에 정보를 조사해 두었을 경우 후반 판정에서 보너스를 받을 수 있습니다.

이 방식으로 앞선 선택이 다음 상황에 영향을 주는 **연속적인 플레이 경험**을 구현했습니다.

---

### 6. 다중 엔딩

플레이 결과에 따라 서로 다른 엔딩으로 이어집니다.

- TRUE END
- NORMAL END
- BAD END 1
- BAD END 2
- BAD END 3

엔딩은 단순히 마지막 버튼 하나로 결정되지 않고  
플레이 중의 생존 상태, 조사 결과, 도구 획득 여부 등의 영향을 받습니다.

각 엔딩에는 별도의 엔딩 카드 이미지와 결과 화면이 제공됩니다.

---

### 7. 시스템 로그

게임 중 발생한 주요 사건을 시간순 로그로 기록합니다.

- 조사 결과
- 아이템 획득
- 위험 이벤트
- 상태 변화
- 스테이지 진행

이를 통해 플레이어가 자신의 선택과 결과를 다시 확인할 수 있도록 구성했습니다.

---

### 8. Web Audio API 효과음

별도의 MP3 음원에 의존하지 않고 브라우저의 **Web Audio API**를 활용해  
인터랙션에 필요한 효과음을 생성합니다.

주요 효과음:

- UI 클릭
- 주사위 굴림
- 성공 / 실패
- 위험 경고
- 글리치 연출

---

### 9. 반응형 UI

기본적으로 PC 와이드 화면에서 게임 정보가 한눈에 보이도록  
`캐릭터 시트 / 내러티브 / 시스템 콘솔`의 3영역 구조를 사용했습니다.

화면이 좁아지면 레이아웃이 재배치되고,  
캐릭터 정보와 시스템 로그는 접을 수 있는 패널 형태로 전환됩니다.

모바일 환경에서도 최소한의 플레이가 가능하도록 대응했습니다.

---

### 10. 접근성 및 사용자 설정

설정 메뉴에서 다음 옵션을 변경할 수 있습니다.

- 기본 / 큰 글씨
- 번쩍이는 화면 효과 제거

설정값은 `localStorage`에 저장되며 재접속 시에도 유지됩니다.

또한 운영체제의 `prefers-reduced-motion` 설정을 감지해  
타이핑 및 주사위 애니메이션을 줄이도록 처리했습니다.

## 구현 포인트

### 상태와 UI 분리

처음에는 게임 특성상 하나의 컴포넌트에 조건문이 집중되기 쉬웠지만,  
진행 로직을 `useGameEngine`, reducer, stage handler로 나누어  
렌더링 컴포넌트가 화면 표현에 집중할 수 있도록 구성했습니다.

### 데이터 기반 시나리오 구성

아이템, 설문, 컨디션, 시나리오 텍스트를 별도 데이터 파일로 분리해  
게임 내용이 바뀌더라도 UI 구조를 크게 수정하지 않도록 설계했습니다.

### 이전 선택이 다음 분기에 영향을 주는 구조

단순히 다음 화면으로 이동하는 방식 대신  
아이템과 플래그를 누적하여 과거의 선택이 이후의 판정과 엔딩까지 연결되도록 구현했습니다.

### UI 애니메이션과 게임 로직 분리

주사위 연출은 시각적 애니메이션과 실제 판정 데이터를 분리했습니다.  
화면 효과가 비활성화되어도 게임 결과에는 영향을 주지 않습니다.

## 테스트

핵심 게임 로직은 Node.js 기본 테스트 러너를 이용해 테스트합니다.

현재 테스트에서는 다음 내용을 확인합니다.

- reducer의 불변성과 초기화
- D20 전체 눈금의 판정 결과
- 캐릭터 및 컨디션 데이터
- 이미지 asset 연결 상태
- 중복 조사 시 AP 중복 차감 방지
- 핵심 도구 획득 여부에 따른 Stage 1 분기
- BAD END 1 / 2 / 3 진입 조건
- 전체 스테이지 정상 진행
- TRUE / NORMAL END 조건

총 **11개의 게임 로직 테스트**가 포함되어 있습니다.

```bash
npm test
```
