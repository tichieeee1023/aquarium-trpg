# 아쿠아리움: 심해의 균열 — 시리즈 UI 적용 기록

## 기준과 작업 범위

텍스트로그 게임 1인 `subway-trpg`의 현재 소스를 UIUX 기준으로 사용했다. 게임 2인 `aquarium-trpg`만 수정했다. 첨부 코드는 아쿠아리움 직군·구역·판정·엔딩의 참고 자료이며 문서 내 주석은 사용자 지시로 취급하지 않았다.

## 이어받은 화면과 연출

- 동일한 MainLayout과 전체 스타일: 프레임, 글씨 크기, 색상, 둥근모 서체, 반응형 배치.
- 타이틀, 타이핑 프롤로그와 건너뛰기, 재방문 시 프롤로그 생략.
- 동일한 헤더의 AP·HP·SAN, 사운드·설정·도움말·힌트. 아쿠아리움에서는 배터리 대신 수위를 표시한다.
- 사원증 미리보기와 확인, 캐릭터 시트, 인벤토리, 왼쪽 패널 하단 엔진 푸터.
- 장면/상황 설명 접기, 조사 HUD 및 액션 카드, 작은 화면에서 캐릭터와 시스템 로그 접기.
- 타이핑 서사 모달: 다음/바깥 클릭/Esc로 텍스트 완성 후 진행. 조사 결과와 획득 도구 표시.
- 동일한 Canvas D20, 회전 이미지, 성공/실패/대성공/대실패 이미지, 결과 확인.
- 피해와 최초 암전 시 화면 반전, 설정에 따른 효과 제거와 주사위 연출 생략.
- 연결 단절 전환, 엔딩 카드·타이핑·크레딧, 엔딩 도감, 전체 수집 축하와 후일담.

배경·캐릭터·도구·엔딩 이미지는 아쿠아리움 에셋을 사용한다. 직군 4종, 구역 5곳, 엔딩 7종과 기존 아쿠아리움 판정 규칙을 유지한다. 가방 5칸 제한에 맞춰 가방 정리를 제공한다. 기록 저장은 플레이 로그 JSON이다.

## 구성 및 데이터 분리

`src/App.jsx`가 시리즈 컴포넌트를 조립한다. `src/hooks/useAquariumGame.js`는 아쿠아리움 리듀서를 기존 화면의 props 형식으로 연결한다. 게임 데이터는 `src/aquariumEngine.js`, 직군·에셋·엔딩용 연결 데이터는 `src/data/`에 있다. 공용 원본을 수정하거나 지하철 폴더를 런타임에 참조하지 않는다.

설정, 오프닝, 엔딩 수집, 완료 축하 저장 키는 각각 `aquarium-settings-v1`, `aquarium-opening-seen-v1`, `aquarium_2345_endings`, `aquarium-completion-celebrated-v1`이다. 지하철 저장 데이터를 공유하거나 변경하지 않는다.

원본 ZIP 다운로드의 누락된 프로젝트 백업, 가방 초과 시 잘못 켜지는 장비 플래그, 실패 피해 누락, 컨디션 DEX 및 게이지 표시 오류 수정은 유지했다. 압력·냉각기·키카드 등 원본에서 엔딩에 연결되지 않은 플래그는 새 엔딩 조건으로 확장하지 않았다.

## 검증

추가 에셋 `item_gear_wetsuit.webp`, `item_tool_sedative.webp`, `item_tool_hex_wrench.webp`를 소지품에 연결했다. 타이틀은 `scene_intro_aquarium.webp`, 전체 엔딩 수집 후 진상 파일은 `scene_classified_truth.webp`를 사용한다. 진상 내용은 사용자가 제공한 「프로젝트 심해 침식 — 최종 종합 보고서」로 교체했다. 문서 분류·파일 번호·익명 감사 컨소시엄·두 사건·최종 결론·ARCHIVED 상태를 포함하며 국가/정부 기관명을 추가하지 않았다. 보고서의 시각 표기는 제공 텍스트를 유지했다.

`node tools/verify-new-assets.mjs`에서 6/7 수집 시 잠금, 7/7 수집 시 해제, 보고서 전체 문장 일치, 데스크톱/모바일 진상 모달, 인트로·진상·새 소지품 이미지 디코딩을 확인했다.

## 지하철 게임 기준 UIUX 교차검증

아쿠아리움은 지하철 게임의 메인 프레임, 타이틀/프롤로그, 설정·도움말·힌트, 사운드, 타이핑 서사, D20 연출, 엔딩·도감, 모달 포커스 처리와 모바일 접힘 패널을 같은 구현으로 사용한다. 아쿠아리움 전용 차이는 수위 HUD, 5칸 가방, 7개 엔딩, 최종 진상 파일이다.

교차검증에서 발견한 차이는 수정했다. 4칸만 보이던 인벤토리를 5칸으로 고쳤고, 엔딩 크레딧 시각을 23:45로 맞췄으며, 도움말의 후일담 표기를 최종 진상 파일로 교체했다. 사운드 토글에는 현재 상태를 설명하는 접근성 레이블을 추가했다. 개발 중에만 동작하는 `Ctrl+Shift+F10` 전체 엔딩 도감 단축키도 지하철과 같은 조건으로 추가했고, 배포 빌드에서는 무시되는 것을 확인했다.

`node tools/verify-ux-parity.mjs`는 포커스 복귀, 단축키, 5칸 가방, 사운드 레이블, 힌트, 큰 글씨/320px 화면을 검사한다. `node tools/verify-production-guard.mjs`는 배포 미리보기에서 개발 단축키가 동작하지 않는지 검사한다.

`npm run build`, `npm run lint`, `npm test`를 통과했다. 엔진 회귀 테스트 5개는 이미지 경로, 컨디션, 가방/장비 플래그, AP/중복 조사, 소모품/HP 소진을 검사한다.

`node tools/verify-series-browser.mjs`는 실제 Chrome으로 다음을 검사한다: 타이틀/프롤로그, 설정/도움말/힌트, 여성 사원증 확인, 헤더/푸터, 서사/주사위 모달, 320~1440px 및 가로 화면의 반응형 계산 스타일, 7개 엔딩 분기/수집, 후일담, 재시작, 기록 다운로드, 지하철과 저장 키 분리 및 런타임 오류. 엔딩 분기는 난수를 고정해 검증하며 확률 균형 검증은 아니다. 스크린샷은 `artifacts/series-review/`에 있다.

복사된 지하철 전용 게임 엔진/기존 테스트 일부는 새 App에서 사용하지 않는 자료로 남아 있다. `npm test`는 아쿠아리움 엔진 테스트를 실행한다.
